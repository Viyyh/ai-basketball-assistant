# AI 篮球分析

给青少年球队教练用的比赛视频分析工具：录一场球，拿到一份能看、能点开、能信的投篮与阵型报告。

当前状态：**v1.1 范围已定，仓库刚搭好骨架**。契约、参数层、设计语言是真实的；后端与 AI 推理尚未开始。

## 怎么跑

只依赖 Node ≥ 20 和 Python 3.11+，不需要 `npm install`。

**契约校验（24 项）**

```bash
cd contracts && npm test
```

**参数层（Python 37 项 + JS 1020 项）**

```bash
cd reference/legacy-demo && node scripts/verify.js
```

**预览 demo 的界面**（浏览器打开即可，无需构建）

```bash
open reference/legacy-demo/miniprogram/preview/index.html
```

## 契约是什么，为什么先做它

报告是 AI 流水线产出、后端存、前端渲染的**同一份数据**。它一旦漂移，症状是"页面能打开、数字是错的"——这类错误不会报错，只会让教练从此不信这个产品。

所以先把数据形状钉死，再写代码：

- `contracts/report.schema.json` —— 结构约束（`additionalProperties: false`，多一个字段就报错）
- `contracts/validate.mjs` —— 两层校验：结构（JSON Schema 子集）+ 语义（10 条跨字段规则）
- `contracts/fixtures/sample-report.json` —— 一份"什么都有"的真实形态样例，所有测试都基于它

语义校验里最关键的两条：

- **R7** 所有统计数字必须能由事件重算出来。手填的 `points`、多算的 `shots_made` 会被抓出来。
- **R8** `coverage`（数据完整度）必须与事件数量对得上。报告上每一句"基于 N/M"都有唯一出处。

另外三条硬规则写在 `report.schema.json` 的 `x-hard-rules` 里：参数只能由参数层产出、投篮分值只能由几何判定产出、球员归属只能由教练写入。

## v1.1 要做的功能

完整表在 `docs/scope-v1.1.md`，这里只列用户能感知到的变化：

**A 层 · 让数字变可信**
1. **我方 / 对方分栏**——报告不再混算两队数据（这是原 demo 最危险的一处）
2. **进攻方向**——全场两个篮筐，按节记录进攻方向，热图不再镜像
3. **补一次出手 / 这不是投篮**——AI 漏检的 15% 和误检的，教练都能修
4. **从相册导入**——不用非得现场用小程序录

**B 层 · 让球员可分析**
5. **球员数据卡**——每人出手分布、命中率、弧外命中率，每个数字点开能看片段
6. **三维评分**——终结 / 中远投 / 参与度，A–D 分档，样本不足显示 INSUFFICIENT
7. **数据完整度**——"基于 3/5 场"，缺数据时明确说缺

**C 层 · 缓做**（UI 保留，暂不接后端）：战术板、对手库、套路演练、实时分析、分享导出、3x3 完整规则

## 还没验证的假设

按危险程度排：

1. **单机位能不能做出逐人分析**——这是产品成立的前提。号码即身份只是 v0 的权宜，真正的同场次跟踪还没验证过。
2. **相机长录是否可靠**——40 分钟、切后台、发热、中断，一次真机都没试过。
3. **上传链路**——2GB 视频在弱网下的进度、断点、失败重试。
4. **青少年三分线 5.80m** —— 参数层里是假设值，测试已把它固化，改常量要改一批用例。
