图例说明

  • 蓝小程序端：只承担"录、传、看、补录"四件事，不承担计算
  • 绿后端服务层：业务编排，不做重计算
  • 黄AI Pipeline：全部跑在一台 GPU 服务器上，队列驱动，串行处理每场视频
  • 紫存储层：原始视频与切片走对象存储，结构化数据走数据库
  • 灰虚线实时入口仅占位，链路第一版不接通

数据流关键点

  • 上传走 HTTPS 直传对象存储（STS 临时凭证），避免经过业务服务器中转，节省带宽与运维成本
  • AI Pipeline 完成时把结果分成两路：结构化事件 → 报告 JSON；片段视频 → 对象存储的切片桶
  • 报告查询服务同时读数据库（教练补录的球员归属）与报告 JSON（AI 输出），做合并
  • CDN 只分发切片，不分发原视频，控制成本与安全边界

图二：教练视角的完整使用流程

四条泳道：教练、小程序、后端服务、AI Pipeline。按编号 1-16 从上到下读。

sequenceDiagram
    autonumber
    actor Coach as 教练
    participant MP as 微信小程序
    participant SVC as 后端服务
    participant GPU as AI Pipeline

    Note over Coach,GPU: 阶段一 · 赛前准备
    Coach->>MP: 新建活动 · 选模板（比赛 / 团队对抗 / 套路演练）
    MP->>SVC: 创建活动 + 上传名单
    Coach->>MP: 录入首发名单 / 分组 / 套路标签库

    Note over Coach,GPU: 阶段二 · 现场录制
    Coach->>MP: 架好手机 · 场边高处 · 点"开始录制"
    MP->>MP: 本地录像 · 40 分钟连续
    Coach->>MP: 结束 · 点"停止录制"

    Note over Coach,GPU: 阶段三 · 上传与云端处理
    MP->>SVC: 申请上传凭证（STS）
    MP->>SVC: 直传对象存储（断点续传 · 可后台）
    SVC->>SVC: 上传完成 · 任务入队
    SVC->>GPU: 拉起处理任务
    GPU->>GPU: 场地标定 → 检测 → 跟踪 → 事件识别 → 阵型采样
    GPU->>GPU: 视频切片（每个事件 8-15 秒）
    GPU->>SVC: 回写报告 JSON · 通知就绪

    Note over Coach,GPU: 阶段四 · 报告与补录
    SVC-->>Coach: 推送"报告已生成"
    Coach->>MP: 打开报告 · 浏览热图 / 阵型 / 时间轴
    loop 对每一个待补录事件
      Coach->>MP: 点击事件卡片
      MP->>SVC: 拉取 8-15 秒片段（CDN）
      MP-->>Coach: 播放片段
      Coach->>MP: 从名单选人 · 标注"这一分是谁"
      MP->>SVC: 保存补录结果
    end
    Coach->>MP: 标记"本场完成" · 归档到历史

四个阶段的耗时预期

阶段教练操作耗时说明
赛前准备 2-5 分钟 名单可以预先在球队管理里存好，赛前只是勾选首发
现场录制 0 分钟（全程挂机） 手机架好按一下就完事，中间不需要操作
上传 + 云端处理 0 分钟（异步） 视频上传 10-30 分钟取决于带宽；AI 处理 20-60 分钟；总耗时约 30-90 分钟。这段时间教练可以离开
补录 10-15 分钟 / 场 一场比赛约 60-100 个事件，教练对着片段选人。这是最大的手工成本，UI 必须打磨到"顺手"

三种场景的差异点

阶段比赛训练 · 团队对抗训练 · 套路演练
赛前准备 首发名单 + 对手 + 比分 分组名单（红队 / 蓝队） 套路清单（如"挡拆外弹 8 次"）
录制中 全程挂机 全程挂机 可选：每段套路起止点按"标记"
报告结构 时间轴 + 节次切分 时间轴 · 无节次 按套路分段 · 每段独立展示
补录 逐个事件选人 逐个事件选人 逐个套路成功/失败判定

关键决策的落点

  • 录后上传而非实时：阶段三的箭头是教练主动"停止录制"后才启动，实时入口不出现于此流程
  • 断点续传：MP 与 SVC 之间的上传通道允许小程序进入后台、断网、微信进程被杀之后恢复
  • 补录闭环：整个产品价值最依赖这一段——从教练点开事件 → 看片段 → 选人 → 保存。这段交互要在设计稿阶段就打磨
  • 异步通知：AI 处理完成后走微信订阅消息或小程序内红点，教练不需要盯着进度条等

附：数据流的一句话版本

教练录一段 40 分钟视频 → 视频进对象存储 → 队列通知 GPU 服务器 → AI 拆成"事件表 + 阵型采样 + 切片视频"三路产出 → 事件表和阵型写成报告 JSON，切片进 CDN → 教练打开报告时读的是合并了"AI 输出 + 教练补录"的视图 → 补录结果写回数据库，与原视频和切片一一关联。
