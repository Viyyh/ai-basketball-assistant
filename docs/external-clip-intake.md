# 外部视频接收与多标签审核

2026-11-04。按用户要求实际采集片段，不能把网址目录当已取得的素材。

第一来源为作者公开提供下载方法的PlayOn篮球样例仓库：https://github.com/playon/basketball-analysis-samples 。使用其中的官方HLS，从600至4650秒每150秒取一个15秒窗口，最多28条；已有文件复用，每段90秒超时、两路并行。它们来自同一场比赛，不代表28个独立来源或覆盖了普通手机实拍。只取得视频片段，不导入球员真实姓名名单。

执行 `python3 scripts/collect_public_pilot.py`；原片段与manifest在data/public-sources/playon-pilot。记录作者页面、媒体地址、请求偏移、实际时长、转码输出哈希、字节数、失败状态与已查看提示。当前为代表性间隔取样，不是已训练的战术探测器，也不声称每条都包含有效战术。

第一批8个窗口各查看3张抽样图，其中2400秒窗口的抽样为空场/暂停，作为负样本候选；其余含推进、多人站位、近筐及停顿等线索。仅抽样不能确认整个片段是否为负样本，必须播放后判断。后续新增窗口没有继承这些视觉确认。

## 人工入口

“开启本地审核.command”的首页增加“新采集片段审核”，单独入口为127.0.0.1:8017。远程统一入口增加acquired应用，使用相同账号白名单与强制署名；默认owner/reviewer可审核，viewer只读。下次按需启动时加载新服务，不自动打开公网。

新页面支持多个标签、片段内部起止时间、参与者/关系、证据说明和confirmed/uncertain/rejected决定。需要观看证据；标签不在词表、区间越界、媒体哈希变化或旧版本提交会拒绝。更正保留SQLite历史。

数据独立存于data/library/acquired-review.db，不覆盖旧主库、独立二审或实拍身份库。confirmed只代表用户核对了所填区间，不自动获准训练，不算原视频全片确认，也不是模型准确率。

## 扩量原则

先用这批验证审核效率和标签定义，然后引入不同场地、机位和来源。优先级应结合完整上下文、领域差异、重复程度、模型分歧和可见性；当前尚未实现模型分歧自动排序。每个已标片段至少保留事件类型、时间、参与者、可见证据和未知原因。

原作者公开给出样例获取方式并描述概念验证用途；媒体长期训练与再分发条件仍单独核对。当前片段不进入公开Git仓库，也不进入training_ready。按来源整组隔离，不能将同场相邻片段同时用于训练和独立盲测。

FineSports、BASKET等来源的申请条件仍需分别处理；不会绕过登录、条款或媒体访问限制。公开视频多，不等于可以省略溯源、标签质量控制或独立测试。

本轮实际结果：28/28个窗口取得，实际416.72秒、266.9MiB；不要把请求的28×15秒直接写成精确成片时长。全部文件哈希与登记一致；尚无真实人工投票。全量回归209项通过，私有媒体不提交Git。
