# 仓库结构与数据流

## 分层

```
┌──────────────────────────────────────────────────────────────┐
│ 前端（未开工）                                                │
│   消费报告 JSON + params 段，不做任何几何计算                  │
└───────────────▲──────────────────────────────────────────────┘
                │ HTTP
┌───────────────┴──────────────────────────────────────────────┐
│ services/api · FastAPI                                        │
│   /v1/params/resolve   参数解析（唯一出口）                    │
│   /v1/activities       活动增删查                              │
│   /v1/activities/{id}/report  报告寄存（SQLite）               │
└───────────────▲──────────────────────────────────────────────┘
                │ 报告 JSON（契约 v1.1）
┌───────────────┴──────────────────────────────────────────────┐
│ services/pipeline · 视频 → 事件 → 报告                        │
│   v1.1 现状：mock（真实几何判定 + 脚本化事件）                 │
│   未来：去噪 → 标定 → 检测 → 跟踪 → 投篮判定 → 归属           │
└───────────────▲──────────────────────────────────────────────┘
                │ 参数（resolve 的产物）
┌───────────────┴──────────────────────────────────────────────┐
│ packages/params · 唯一真源                                    │
│   resolve(赛制, 年龄段) → 场地 / 三分线 / 规则 / 跟踪参数      │
│   CourtGeometry.judge()  → 分值 + 界面标签 + 越界检查          │
└───────────────▲──────────────────────────────────────────────┘
                │ 结构 + 语义
┌───────────────┴──────────────────────────────────────────────┐
│ contracts/ · 报告契约 v1.1 + 零依赖校验器                      │
│   report.schema.json   结构（additionalProperties: false）     │
│   validate.mjs         语义 R1–R10（数字对不对）               │
└──────────────────────────────────────────────────────────────┘
```

依赖方向是单向的：`contracts ← params ← pipeline → api → 前端`。
反过来依赖（比如 params 去 import pipeline）说明分层错了。

## 数据流

```
录像/相册视频
   │ ① 上传（对象存储 key，不进库）
   ▼
标定 → 单应矩阵 → 像素坐标变米制坐标
   │ ② calibration.ok=false 时必须在报告页阻断，不出坐标类结论
   ▼
检测 + 跟踪 → 轨迹
   │ ③ 第一版只取"出手瞬间"，不承诺逐人 ReID
   ▼
出手判定 → CourtGeometry.judge()
   │ ④ 分值、三分/二分标签只能来自这里
   ▼
事件流（含 source / status / team_side）
   │ ⑤ 教练补录归属、补事件、排除误检
   ▼
报告（契约 v1.1）
   │ ⑥ 统计量由 ACTIVE 事件重算，coverage 由事件数派生
   ▼
API 寄存 → 前端渲染
```

## 各组件的职责边界

| 路径 | 负责 | 不负责 |
|---|---|---|
| `packages/params/` | 赛制/年龄段参数、三分线几何、分值判定、界面标签 | 不认识视频、不认识数据库 |
| `contracts/` | 数据结构与语义约束 | 不含业务逻辑，不存数据 |
| `services/pipeline/` | 视频 → 事件 → 报告 | 不做归属（AI 恒为 null）、不自己算分值 |
| `services/api/` | HTTP 边界、持久化 | 不做几何计算、不改报告内容 |
| 前端（未开工） | 渲染与交互 | 不复制参数表、不自己数统计 |

## 三个不变式

1. **params 只有一处产出。** 报告里的 `params` 段必须原样来自 `resolve()`，pipeline 只透传（契约硬规则 #1）。
2. **分值只有一处判定。** `shot_value` / `label_zh` 只能由 `CourtGeometry.judge()` 产出（硬规则 #2），pipeline 不得自行判断几何。
3. **统计必须可重算。** `team_stats` / `opponent_stats` / `coverage` 必须等于由 ACTIVE 事件重算的结果（R7、R8）。任何手填都会在 CI 被抓。

## 版本与兼容

- 契约版本在 `report.schema.json` 的 `schema_version` 上，当前 `1.1`；`additionalProperties: false` 意味着加字段必须升版本。
- 校验器以 `schema_version` 的 `const` 断言锁定版本，防止 pipeline 仍产出 1.0。
- 评分规则用 `rating_rules: "v0"` 单独版本化：调阈值升 `v1`，历史报告仍按 `v0` 可回算。
- `docs/prd.md`、`docs/plan.md` 是**冻结的历史文档**，不在其中修订；本版增量写 `docs/scope-v1.1.md`，决策写 `docs/decisions.md`。
