# 项目完整说明与操作指南

更新：2026-11-03。本文以当前代码和本地数据库快照为依据；历史PRD、计划及演示报告不代表已经实现的自动分析能力。

## 1. 项目是什么

面向大众篮球训练的视频分析研发项目。最终希望不同用户在不同场地上传视频后，获得可回看的个人表现、投篮与配合信息。当前最成熟的闭环是：接收原片 → 检测/人工观察生成候选 → 确认球员和事件 → 保留纠错历史 → 汇总带证据的个人记录。

它尚不是可靠的全自动篮球统计产品。现在的用户版PDF和球员资料页结合助手视觉抽样与人工决定，不能用来证明模型已经自动理解所有动作。提供更多标签，也不意味着模型已经学会这些标签。

## 2. 日常使用：先看这里

### 自己在电脑上审核

在Finder进入仓库根目录，双击“开启本地审核.command”。统一首页为 http://127.0.0.1:8015/ ，无需密码，只有本机能用。首页通往个人复盘、独立二审、主库及外部来源审核，并列出连续视频分段。

首次打开可能要等子服务启动后刷新。终端需要保留；Ctrl+C结束本次启动的服务。若服务本来已运行，再次双击只打开入口，不重复启动。结束这次启动不会删除数据库或原片；原来就存在的独立服务不由启动器强制关闭。

### 请其他人协作

双击“开启远程审核.command”，等待显示本次HTTPS网址，分享该网址及对应审核账号。双击“查看远程审核状态.command”可重新取得地址。审核完双击“关闭远程审核.command”。关闭浏览器/终端不等于关闭远程分享。

远程当前采用按需模式，不在下次登录电脑时自动开启。分享期间有进程守护；电脑休眠、断网或关机会中断。临时隧道重新启动可能换网址；账号密码不因开关变化。实时网址与凭据只在data/access，不写入公开文档。

reviewer可修改个人事件、提交独立二审；主库与JSON导出仅owner。其他账号可按需单独创建。独立二审不会自动合并主库。全部远程访问先认证，数据库文件不是公网下载资源。详细权限与管理命令见remote-review-access.md。

## 5. 四套数据库为什么分开

| 本地文件 | 用途 | 重要边界 |
|---|---|---|
| data/library/library.db | 原始素材、外部标注与主人审历史 | 不把外部结构检查直接批准训练 |
| data/library/external-review.db | 独立第二轮审核 | 不自动覆盖或合并主库 |
| data/library/player-review.db | 两段实拍的球员、事件、个人设置与复核范围 | 当前个人统计来源 |
| data/app.db | 业务API活动及报告 | 与以上审核库尚未完全整合 |

不应把不同库的行数相加当成独立训练样本数，也不应把两个审核者确认同一事件算成两次出手。

## 6. 个人报告如何产生

进入个人复盘后先核对身份。没有姓名时用衣色/队伍＋号码，有姓名则显示姓名及原号码线索；姓名不是主键。然后逐条核验候选，补上系统遗漏事件，确认出手者、动作、起止和结果。

只有原片状态有效、身份已确认、事件已确认且为出手，才进入对应个人统计。made、missed、unknown分开列出；命中率仅为made/(made+missed)，分母0为待确认，不显示0%。它描述已确认且结果已知的子集，不是完整比赛命中率。

看完连续区间并补齐所有出手后才登记“已复核”。覆盖率是审核范围，不是模型准确率。更正保留历史，旧版本提交409；同源出手区间重叠时阻止双计，需要核对或缩小区间。

个性化配置是用户说明，未知保持null。它不是视频标定，当前还不驱动旧参数层或自动得分。分析目标是用户诉求，不是已实现能力列表。

## 8. 开发、检查与安全边界

本机已验证Python3.12与CPU推理；检测需要ffmpeg和requirements-local-tested.txt；审核/API需fastapi、uvicorn、httpx；契约与报告入库需要Node>=20。具体安装和推理命令见根README及docs/local-analysis.md。根目录.command目前绑定本机Python解释器，换电脑应重新配置环境，不能直接假定双击可运行。

`./scripts/verify.sh` 检查契约、参数、pipeline、API与样例一致性；`./scripts/check-local.sh` 包含数据、审核、导出、个人设置、评测及网关检查。真实用户投票不用于自动测试，写入测试使用合成或临时副本。

原片、SQLite、私有观察、身份资料、密码、实时域名和日志保留本地。新克隆不会自动获得现有素材、模型权重或凭据。备份数据库应使用SQLite backup，不在写入过程中直接复制单个db文件；云迁移时也要单独迁移审核历史与来源哈希。

## 9. 后续按什么顺序推进

1. 裁决二审7条不确定记录，保留分歧与处理原因。
2. 完成两段实拍的连续事件标注，而不仅是现有候选；未知结果和无事件片段都要保留。
3. 先评测出手检索、身份归属和结果判断，再按错误分布补检测/跟踪数据。
4. 扩充传接球、无球移动和掩护参与关系标签，建立时序/关系评测；不能只训练静态目标检测器就期待学会战术。
5. 整合参数、个人设置与报告规则，再接正式上传。
6. 有云账号后部署私有对象存储、应用和数据库，随后接小程序。仅上传视频不等于项目已上云。
