# 从目标检测到篮球事件理解

新增事件词表见datasets/event-taxonomy.json，审核页已支持按传球/持球、无球移动、掩护配合、站位防守分组选择。旧标签ID保留，新选择只在提交审核后写入，不自动改历史票。依据FIBA/WABC教学目录与FIBA Europe术语资料整理；这是标注词表，不是新增模型识别率结论。

## 标签与视频证据

- 传球：记录出球者、接球者、球离手及接球时间；球权变化不必然是传球成功，也可能抢断或争抢。
- 无球切入：记录同一球员连续路径、是否持球及相对篮筐/防守者的方向；单帧站位不能证明切入。
- 掩护：记录掩护者、使用掩护者、相关防守者和前后连续过程；靠近不直接等于有效掩护。
- 挡拆：先确认持球掩护，再分别记录顺下/外弹后续；是否接球、是否创造空间和是否得分分开标。
- 站位：记录时间区间、球员与球的图像位置、可见区域；没有场地标定不输出米制间距，不强判站位优劣。
- 防守：协防、换防、扑防、卡位记录参与者关系及动作；动作发生不等于防守成功。

每条事件应包含source_id、start/end、actor_ids、对象/参与关系、标签集合、证据帧、可见性、unknown原因和审核版本。多事件可重叠，一段可同时存在传球、切入和掩护；当前旧战术页面仍为主标签单选，复杂组合放入文字证据，后续再实现结构化多标签，不能假称已支持。

## 提取与学习的实施顺序

1. 先建立同一球员跨帧轨迹、球可见性与持球候选。背景球员和遮挡区应排除，身份不稳时停止事件归属。
2. 基于轨迹形成传接球、持球突破、无球移动候选；规则或视觉模型产出都保留为candidate，不当真值。
3. 对连续时间窗标注参与者、起止和关系；保留无事件负样本、失败配合、遮挡和unknown。不能仅有战术名字或精彩集锦标题。
4. 从基础动作组合候选团队配合，先做可回看的事件检索，再评估战术分类。站位评价需要规则和场地坐标；不和动作识别混成一个分数。
5. 数据按来源/会话分组冻结，独立复核；时间窗IoU、参与者归属、类别多标签precision/recall、未知拒答与每分钟误报分别评估。现有出手评测器不能直接充当战术评测器。
6. 有足够已核验连续片段后，才训练或微调时序事件模型；先用固定基线做对照。此轮未训练新模型，未完成全片事件真值，未实现自动战术判定。

现有系统不只缺少选项，而是缺少连续轨迹、关系标签、独立事件真值及跨场地评测。第一目标应是传球/接球与无球移动检索，再逐步加入掩护、挡拆与站位解释，避免一次承诺所有篮球理解能力。
