# 三组参数 PoC

对应《AI篮球分析小程序_第一版范围确认 v0.2》第九节与风险 7.4。

## 这个 PoC 验证什么

范围确认 v0.2 新识别了一条风险：**赛制与年龄段参数取错，会导致"静默的错误数据"**。

它比 AI 精度不足更危险。AI 精度不够时教练看得出来（热图明显偏了），但参数取错时报告看起来完全正常、数字却全错——教练会拿着一个错误的三分命中率去批评球员，而且无从察觉。

本 PoC 用三组参数组合验证这条风险是否真实存在，以及现有设计能否挡住它。

| 组合 | 参数 | 验证目标 |
|---|---|---|
| A | 5对5 + 15岁以下 | 基线参数解析是否正确 |
| B | 5对5 + 12岁以下 | 三分线半径 5.80 m 时判定是否仍准确 |
| C | 3对3 + 半场 | 半场单框标定能否跑通，坐标是否偏移 |

## 怎么跑

不需要安装任何依赖，只用 Python 标准库：

```bash
cd 自研app
py poc/run_poc.py
```

只跑测试：

```bash
cd 自研app/poc
py -m unittest discover -s tests -v
```

## 主要结论

### 1. 同一物理出手点，不同参数 → 不同分值（已证实）

弧顶 6.20 m 处的一次出手：

- U12 / U15（弧 5.80 m）→ **3 分**
- 一线（弧 6.75 m）→ **2 分**

这证明"年龄段与赛制必须必填、不能有默认值"不是过度设计。

### 2. 用错参数的后果可以量化（已证实）

在 5.8~6.7 m 这个青少年比赛的中远距离主力出手区，用成人半径去判 U12 比赛：

```
20 次出手 / 15 次命中
正确参数（弧 5.80 m）→ 命中三分 15 个
错误参数（弧 6.75 m）→ 命中三分  3 个
漏判 12 个，占 80%
```

报告上完全看不出异常——热图形状合理、事件数量正常、命中率是个像样的数字。

### 3. 三分线有两种几何，不能共用一套判定（PoC 阶段的新发现）

- **FIBA 成人 5v5**：弧线（6.75 m）+ 底角直线段（横向 6.60 m）。底角三分比弧顶三分更近，这是真实规则
- **FIBA 3x3**：整条弧都是 6.75 m，**没有底角直线段**
- **青少年小半径场地**：半径 5.80 m < 底角横向 6.60 m，弧线永远碰不到底角直线的位置，几何上**只能退化为纯弧线**

第三条如果没处理，会出现"底角直线段落在弧线内侧"的自相矛盾配置，判定逻辑给出错误结果且不报错。`validate_params_for_pipeline()` 能拦住这种配置，测试里有覆盖。

### 4. 3对3 是完全独立的规则集（已实现）

半场单框 15×11 m、12 秒进攻时限、弧内 1 分弧外 2 分、单节 10 分钟或先得 21 分、快攻识别关闭、**报告不得出现"三分"字样**（改称"远投(2分)"）。

坐标范围也与全场不同：全场 x ∈ [-1.575, 26.425]、y ∈ ±7.5；3x3 半场 x ∈ [-1.575, 13.425]、y ∈ ±5.5。用全场模板处理 3x3 录像会导致坐标整体偏移，越界检查能检出。

### 5. 跨赛制聚合在数据层被拦截（已实现）

`aggregate_guarded()` 遇到混合赛制直接抛 `CrossFormatAggregationError`。

实证：5 场数据（3 场 5v5 + 2 场 3v3），分开算是 5v5 胜率 67%、3v3 胜率 50%，合并算会得到 60% ——三个数字互不相同，合并出来的那个在篮球意义上无效。

这对应球队页设计 v0.2 屏 02 的决定：**赛制筛选不提供"全部"选项**。

## 两个待核实数值

改一个常量的事，但改错会导致整份报告系统性偏差，且教练无法察觉。**建议在写 pipeline 代码之前确认。**

| 数值 | 当前取值 | 问题 | 确认方式 |
|---|---|---|---|
| 青少年三分线半径 | 5.80 m（U8/U12/U15） | 各地联赛常见 5.80 / 6.00 / 6.25 m 不等，这是范围确认 v0.2 采用的假设值 | 问 2-3 位青训教练打的是哪个联赛、看秩序册 |
| 一线单节时长 | 10 分钟（FIBA 官方） | 范围确认 v0.2 的 5.5 节表写的是 4 × 12 分钟（NBA 口径） | 同上 |

`params.py` 里两处都标了 `[待核实]`，`run_poc.py` 第 6 步会把它们汇总打印。

## 被阻塞的部分：视频精度

本机环境探测结果：

```
[✓] Python 3.13
[✗] ffmpeg
[✗] NVIDIA GPU / CUDA（本机为 AMD 核显）
[✗] torch
[✗] ultralytics (YOLOv8)
[✗] 三组真实录像素材
```

因此以下精度指标**尚未验证**，需要素材与 GPU 环境：

- 场地标定精度：单应矩阵重投影误差是否 < 5 像素
- 检测精度：单机位高视角下球员与球的检出率
- **三分识别命中率：范围确认 v0.2 第九节定的验收线是 85%**
- 快攻识别的查准率 / 查全率
- 阵型采样的位置误差

`video_pipeline.py` 已经把 pipeline 的五阶段接口契约固定下来（标定 → 检测跟踪 → 事件识别 → 阵型采样 → 切片），使参数层可以先被完整验证，不必等视频链路就绪。

### 素材规格

| 组合 | 要求 |
|---|---|
| A | U15 五对五全场正式比赛，≥ 20 分钟 |
| B | U12 五对五全场，≥ 20 分钟，**三分线须在画面中可见** |
| C | 三对三半场，≥ 10 分钟 |

统一要求：场边高处单机位、1080p 或以上、≥ 30 fps、画面能看到完整球场线与至少一个篮框、手机固定不晃动（三脚架或看台栏杆）。

组合 B 特别要求拍到三分线本身，否则无法验证"5.80 m 半径下判定是否准确"——标定的地面真值来自画面里的线。
